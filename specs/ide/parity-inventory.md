# Parity inventory: Ycode against Xcode 27.1 (the 2026-11-15 run)

**Status:** boundary spec. This is the full, deduplicated list of the differences between
Ycode 1.0.0-beta.3 and the reference, Xcode 27.1, found by the side-by-side run of
2026-11-15/16, merged with the differences between Ycode's macOS IDE and its Linux IDE.
It is the work list behind [`docs/ROADMAP-1.0.md`](../../docs/ROADMAP-1.0.md). Prose, tables
and measured numbers only: no code, no pseudo-code of the reference's internals, no copied
resources.

- **Reference** values come from black-box recordings of Xcode 27.1 (dirty room). They describe
  observable behaviour, layout and timing.
- **Ycode on macOS** is the same build (commit 514ea9e9, the 1.0.0-beta.3 release) recorded in
  the same session, plus Ycode-side faults seen in its own recordings.
- **Ycode on Linux** comes from the PARITY-LINUX inventory (clean room: Ycode against Ycode,
  phases 1 and 2), whose rows are cited as **L-nnn**. "as macOS" means that inventory found no
  difference for this state; "not checked" means no Linux run reached it.
- Earlier council rows (`specs/ide/fidelity-council.md`) are cited by number.

This spec does not decide owner questions (§4). It does not file issues.

**Measurement conditions.** Both apps ran in turn on the same Mac at 2x (Retina) and 120 Hz,
dark system appearance (one light session), with a 1400 × 880 workspace window unless a row
says otherwise. Times are milliseconds from the **effective input** (the last action of a
step that succeeded; for actions that search the accessibility tree first, the moment the
event was posted). One frame is 8.3 ms. "10–90 %" is the progress of the moving region inside
its own box. Lengths are points (2x pixels / 2). Device rows ran under very high host load:
their shapes and durations stand, their start latencies do not.

**Corrections applied.** The analysts re-measured every timing by region; their numbers
replace the capture's first-pass notes (many "fades" there were a pressed tint followed by a
one-frame appearance, a tooltip fading, or a pane *hiding* because the reference toggles a
pane whose shortcut is pressed while it is shown). Part D's reconciliation supersedes earlier
rows where it says so (§6).

**Themes.** Menus & commands; Window & toolbar chrome; Navigators; Editor core; Editor
overlays (completion, Quick Help, find, rename, Library); Inspectors; Project editor & build
settings; Schemes, destinations & tests; Build, run & debug; Source control; Settings;
Non-source editors; Interface Builder & previews; Device Hub & Organizer; Welcome, New Project
& templates; Documentation, Help & About; Motion system; Accessibility; Performance;
Linux-only gaps. A difference sits in one theme only; motion of shared containers (split
panes, popovers, sheets, tooltips, hover states) is in Motion system, motion of a single
feature stays with the feature.

**The design rule** (owner, 2026-11-06) applies to every row: where the reference has the
element, match it (layout, place, wording, behaviour); Ycode-only elements follow the HIG and
the OS 26 Liquid Glass language; the macOS and Linux IDEs look and behave one to one, so a
row is closed only when both IDEs match. Owner exceptions stand: the line-art language logos
in the navigator, the Ycode mark in the title area, and the macOS toolbar overflow item
(row 218, revisit in §4).

## 4. Decisions for the owner

These need the owner's choice before the clean work starts. They are listed neutrally; this
spec does not choose. The rows they hold are marked "owner decision" in §7.

1. **Coding assistant: pane and Settings** (P-027, P-152, P-153). The reference's pane holds only the conversation list until a conversation starts, and its Settings pane is "Intelligence" (agents with Get, an MCP permission pop-up, chat providers). Ycode shows a full chat with provider notices and a "Coding Assistant" pane built around Ycode's own providers (Ollama, local models, agent CLIs, ACP). Options: (a) mirror the reference's structure and names, folding Ycode's providers into its sections; (b) keep Ycode's pane and Settings as Ycode-only UI designed to the HIG; (c) the reference's empty pane and section order, with Ycode's provider rows inside them.
2. **Device Hub for simulators Ycode does not run on macOS** (P-172, P-173). On macOS the hub lists every simctl simulator but draws an empty outline and answers "Ycode doesn't run this device."; Ycode's own simulators run on a Linux host. The reference shows live screens, a device Settings inspector, its own Device and Controls menus and a menu bar of its own. Options: (a) keep the outline and toast; (b) list only Ycode's own (host) simulators on macOS and hide simctl devices; (c) keep simctl devices read-only with a HIG empty state that leads to Set Up Ycode Simulator; (d) stream a paired host's simulator into the stage (#50, #85); (e) and separately: give the device window its own Device and Controls menus, or keep the IDE's menu bar.
3. **About window** (P-189). The reference shows a titleless 530 × 219 panel; Ycode shows a titled window with version, MIT copyright, repository, licence, notices and an independence note. Options: (a) the reference's layout with Ycode's content (notices behind an Acknowledgments button); (b) keep Ycode's HIG window; (c) the reference's layout, with the independence note kept as a second line.
4. **Ycode-only and Linux-only items** (P-020, P-165, P-219). Ycode adds File from Clipboard, Compare Files…, Integrate ▸ Merge…, Report a Bug…, Get a Simulator Runtime…, Set Up Ycode Simulator…, seven Refactor items; Linux alone has Save All, View Memory, extra context menus, an Open As switch, structured-editor bars and an edited-row dot. Options: (a) keep each where it is (HIG for Ycode-only UI); (b) gather Ycode-only commands in one place (for example the app menu or a Ycode sub-menu); (c) for each Linux-only item: port it to macOS or remove it from Linux.
5. **Cloud entries** (P-016, P-040). Earlier rounds decided that Ycode has no cloud service and omits the cloud notices button. Ycode still shows an Integrate ▸ "Cloud" sub-menu and a Reports Local/Cloud control. Options: (a) omit every cloud entry; (b) keep disabled placeholders where the reference has entries; (c) keep only the Reports control for layout parity.
6. **The reference's own tools and Help items** (P-018, P-021). Open Developer Tool lists Instruments, Icon Composer, Accessibility Inspector, FileMerge and Create ML; Help lists What's New, account and store help and Provide Feedback. Options: (a) omit them; (b) on macOS, launch the installed tools when present (no Apple code shipped); (c) map them to Ycode's equivalents (Gauge, Compare Files) and omit the rest.
7. **Settings rows tied to Apple services** (P-141, P-142, P-146). General's settings-sync switch, Notifications ▸ Distribution and Performance, and the Components rows for the predictive model, Metal toolchain, documentation and an agent download. Options: (a) omit; (b) show Ycode equivalents where one exists (Ycode's own models and simulator runtimes); (c) show them disabled for layout parity.
8. **Library content** (P-088). The reference's Library has Snippets, Media and Color tabs and about 470 snippets; Ycode must write its own snippets. Options: (a) a Ycode-written set covering the same categories; (b) a smaller curated set and user snippets; (c) Media and Color drawn from the project's assets either way.
9. **Interface Builder for macOS documents and the Core Data editor in 1.0.0** (P-161, P-170). Both are XL. Ycode's IB is UIKit-first, draws wireframes and shows an "Experimental" badge; the data model opens nothing. Options: (a) both in 1.0.0 (beta 8 as planned); (b) Core Data in 1.0.0, macOS IB after it; (c) both after 1.0.0, with the badge kept.
10. **Developer Documentation** (P-188). The reference opens a documentation window; Ycode opens the website in the browser. Options: (a) keep the browser; (b) an in-app viewer of the public documentation site; (c) an in-app DocC viewer for the project's and open-source packages' documentation, with the browser for the rest.
11. **The macOS toolbar overflow gap** (P-025). Row 218: the gap before » is 26 pt against 5 pt because Ycode keeps the system overflow item and its morph (owner, 2026-11-13: keep, revisit in beta 4). Options: (a) keep the system item; (b) draw Ycode's own » (closes the gap, loses the system morph).
12. **Syntax Coloring languages** (P-019). The reference lists 58 languages, Ycode 14. Options: (a) grammars for all of them before 1.0.0 (openly licensed grammars); (b) list only languages Ycode colours and add the rest after 1.0.0.
13. **⌘3 on Linux** (P-050). Linux opens a Symbol navigator macOS does not have. Options: (a) Bookmarks on both (move the Symbol navigator elsewhere or drop it); (b) keep the Symbol navigator as a Linux-only ninth navigator.
14. **Capability list** (P-099). The reference lists about 80 capabilities; many need Apple services. Options: (a) list every capability that only writes entitlements and build settings; (b) the full list, with service-backed ones noting what Ycode cannot provision.
15. **Built-in theme editing and Notifications** (P-146, P-151). The reference edits its built-in theme in place and routes build/run notifications through Behaviors; Ycode makes built-ins read-only and has its own "Notify when" switches. Options: (a) follow the reference in both; (b) keep Ycode's read-only built-ins and switches as Ycode-only UI.

# Observations: iPhone 18 Pro on the iOS 27.0 runtime (2026-10-27)

Dirty-room notes by OBS-IPHONE18. Prose only. The clean results are
`specs/simulator/iphone-types.md` (device type, identity, capabilities) and
`specs/simulator/home-apps.md` §4.1 (home screen and launches).

## Why this was looked at

Ycode will boot the iOS 27.0 runtime (24A434) because it ships Maps,
Calendar, Photos, Messages and 13 other apps that 27.1 lacks. Ycode's only
iPhone identity is iPhone Duo (`iPhone19,4`), and 27.0 does not accept that
device type. The owner wants a faithful iPhone home screen on 27.0, so the
facts for a second iPhone identity, iPhone 18 Pro, were collected.

## Devices used

All on this Mac with Xcode 27.1's CoreSimulator, created and deleted by this
session. No other simulator was touched; Xcode's windows were not touched.

| Name | Device type | Runtime | Result |
|---|---|---|---|
| `ycode-test-iphone18-duocheck` | iPhone Duo | iOS 27.0 | `simctl create` refused (error 403 "Incompatible device"); no device was made |
| `ycode-test-iphone18-a` | iPhone 18 Pro | iOS 27.0 | first boot failed ("launchd failed to respond", launchd_sim could not bind to its session) while the host load average was 350; deleted unbooted-to-home and replaced |
| `ycode-test-iphone18-b` | iPhone 18 Pro | iOS 27.0 | the reference device: first boot, layout, environment, launches, two reboots |
| `ycode-test-iphone18-c` | iPhone 18 Pro | iOS 27.0 | second fresh device, only to time the first boot to a drawn home screen and to check that the layout repeats |

The host was busy all the time (load average 50 to 400, another agent's
Xcode audit, an Android emulator). Times below are upper bounds.

## What I saw, in order

1. **The device-type bundle.** `iPhone 18 Pro.simdevicetype` has the same
   file set as the iPhone Duo's: `Info.plist` (bundle identifier
   `com.apple.CoreSimulator.SimDeviceType.iPhone-18-Pro`), `profile.plist`,
   `capabilities.plist`, one framebuffer-mask PDF named by UUID, the
   `sensor_bar_class_04` PDF, a localized name. Its model is `iPhone19,2`,
   product class `V63`, minimum runtime 27.0, created by default for 27.0
   and later. Unlike the iPhone Duo it has no `aliases` key, and its
   `supportedFeatures` lack `com.apple.CoreSimulator.framebuffer.27` and
   `com.apple.touch-id` but have `com.apple.pearl-id` (Face ID). The
   conditional feature list is the same as the iPhone Duo's.
2. **Capabilities are nearly the iPhone Duo's.** A key-by-key comparison
   of the two `capabilities` dictionaries (leaving out `displays`) found
   twelve differences only: product description in `ArtworkTraits`
   ("iPhone 18 Pro" against "iPhone"), `ArtworkDeviceSubType` and
   `subtype` (2622 against 2034), `CompatibleDeviceFallback` (iPhone18,1
   against iPhone18,3), the screen size (1206 × 2622 against 1398 × 2034),
   `DeviceCornerRadius` (62 against 59), model and thinning type,
   model numbers (A3472 against A3447), `marketing-name`, `pearl-id` true,
   `touch-id` false, and `RingerButtonCapability` true. Everything else,
   including the key set and the number types, is the same. So the
   iPhone 18 Pro is a small data change from what Ycode already writes.
3. **Displays.** The device type lists four displays: `LCD` (1206 × 2622,
   integrated, digitizer, on), `TVOut`, `Wireless` (CarPlay) and
   `Resizable` (7680 × 4320 scene, needs the resizable-scene feature). The
   iPhone Duo has the same list plus a second integrated display `LCD-1`.
   On the booted device `simctl io enumerate` showed four display ports
   (1206 × 2622, 7680 × 4320 and two 720 × 480), and `simctl io screenshot`
   without `--display` returned the 1206 × 2622 image. That is unlike the
   iPhone Duo, where the default display is the black inner one.
4. **Runtimes.** `simctl list runtimes -j` lists 33 iPhone types for 27.0
   (iPhone 18 Pro, 18 Pro Max, the iPhone 17 family including 17e and Air,
   back to iPhone 11, both SE models), 31 for 26.5, and only iPhone Duo for
   27.1. iPhone Duo is not in 27.0's list; its own `minRuntimeVersion` is
   27.1, which is enough to exclude it. The 27.0 and 27.1 runtime
   `profile.plist` files differ only in `defaultVersionString` and in
   27.1's `restrictedToDeviceTypes`; the required host services, features
   and environment are the same.
5. **Before the first boot** the new device directory held 56 files
   (17 MB): the sample photos in `Media/DCIM/100APPLE` (five JPEG, one
   HEIC), the Photos, Downloads and media-library databases, the address
   book databases, and `.GlobalPreferences.plist` with `en-US` / `en_US`.
   This is the set `first-boot.md` describes; no `SpringBoard` folder yet.
6. **First boot.** Device b: `simctl boot` returned after 15.8 s (load
   about 60), `bootstatus` reported "Waiting on BackBoard" at 17 s, data
   migration from 18 s (the LaunchServices migrator took most of it), and
   the terminal state at 40.9 s; `IconState.plist` existed at 45 s.
   Device c (load about 220 to 400): `boot` returned at 0.7 s, the terminal
   state came at about 30 s, and the first screenshot that showed the home
   screen was at 48.6 s (the sample before, at 44.7 s, was still the black
   boot screen). In that first drawn frame the two page-1 widgets were
   still blank white tiles; the app icons, wallpaper, dock and search
   button were already drawn. Earlier work recorded 49.1 s for the same
   type at load 900 (`research/notes/ipad-observations.md` §3.1). So a
   first boot reaches the home screen in about 45 to 50 s on this busy
   Mac.
7. **Second boot.** After a shutdown, `bootstatus` reached the terminal
   state in 3.7 s with no migration, but the screen still showed the boot
   logo. With screenshot polling, a later reboot showed the home screen at
   18.1 s.
8. **Environment.** `simctl spawn <dev> /usr/bin/env` gave the launch
   environment (`launchctl getenv` printed nothing for these names, so it
   cannot be used for them). It has the same variable names as the iPhone
   Duo's, including both extended-display variables. The values that
   depend on the device type: model `iPhone19,2`, product class `V63`,
   asset suffix `iphone`, main screen 1206 × 2622, scale `3.000000`, pitch
   `460.000000`, the capabilities path of the iPhone 18 Pro bundle, and the
   version-info string naming the device type "iPhone 18 Pro". The
   extended-display file that the two variables name did not exist in the
   device directory after the first boot (the variables are set anyway).
9. **Layout.** `DesiredIconState.plist` is SpringBoard's
   `DefaultIconState~iphone.plist` unchanged plus `metadata.creationDate`
   and an empty `dockUtilities` array. The 27.0 SpringBoard has no
   size-specific file for 402 × 874 points (the iPhone 18 Pro screen at
   scale 3), so the generic iPhone file is used. 27.0 and 27.1 carry the
   same generic file; only 27.1 has the 466w-678h file of the Duo.
   `IconState.plist` is that layout filtered as `home-apps.md` §3.4
   describes. Two things were new to me:
   - the top level of `IconState.plist` also carries `defaultDisplayName`
     and `displayName` "Folder" and a `uniqueIdentifier` (the root list is
     treated as a folder), and the remaining folder gains `displayName`,
     `listType` "folder", `listUniqueIdentifiers` and `uniqueIdentifier`;
     widgets and stacks gain `displayIdentifier` and `uniqueIdentifier`;
   - the News widget in the Today list changes its `gridSize` from the
     default file's `newsLargeTall` to `extraLargePortrait`; the
     Weather, Tips and Stocks Today widgets are removed (no apps).
   Device c's layout was identical to device b's apart from the generated
   UUIDs.
10. **Visible apps.** `listapps` returned 39 records, which matches a
    count of the runtime's bundles (179 with an Info.plist and an
    executable, 134 of them tagged `hidden`, 6 launch-prohibited).
    Watch (`com.apple.Bridge`) is placed on page 2 on the iPhone; on the
    iPad it was hidden because `watch-companion` is false there.
11. **Launches.** All twelve apps tried returned a pid at once (0.2 to
    1.0 s for `simctl launch`) and were still running 12 s later. Each app
    was terminated before the next launch. Two things matter for anyone
    comparing screenshots:
    - The first permission alert of a fresh device stays on the screen
      after the app that caused it is terminated, and covers every later
      app and the home screen. Maps asked for location; that alert covered
      Calendar, Photos, Messages and News. After a reboot, Health asked to
      send notifications; that alert covered Wallet, Contacts, Files,
      Reminders, Settings and Safari. I did not answer either alert. The
      content behind them was readable.
    - Calendar and Photos were started again in the background after they
      were terminated (new pids in `launchctl list` a few seconds later),
      together with the Spotlight, family and widget-renderer UI services.
12. **First screens** (what the app showed after 12 s, behind the alert):
    - Maps: an onboarding sheet with a lock-screen picture (a "9:41" clock
      and a notification) and the buttons "Enable Notifications" and "Not
      Now"; the location alert on top.
    - Calendar: a "What's New in Calendar" sheet with a red Continue
      button.
    - Photos: a "What's New in Photos" sheet with a blue Continue button.
    - Messages: the conversation list titled "Messages" with two sample
      conversations dated 12/31/00 (the first from +1 (888) 555-1212) and a
      search field at the bottom.
    - News: "Welcome to Apple News" with a privacy paragraph and a red
      Continue button.
    - Health: "Summary" with a Pinned section ("No pinned topics"),
      "Show All Health Data", and the tab bar Summary / Sharing / Browse.
    - Wallet: title "Wallet" with add and more buttons, a "What's New in
      Wallet" card and an illustration of passes.
    - Contacts: the contact list with the sample contacts (John Appleseed,
      Kate Bell, David Taylor, Hank M. Zakroff and others) and an A–Z
      index.
    - Files: "Recents" with a search field, empty, and the tab bar Recents
      / Shared / Browse.
    - Reminders: a "Welcome to Reminders" sheet listing features with a
      blue Continue button.
    - Settings: as on 27.1 (Apple Account row, "Optimizing Search and
      Siri", then the settings list).
    - Safari: the Start Page with a customization card, an iCloud prompt
      ("Not Now" / "Turn On") and the Privacy Report.
13. **Crash reports.** The host's DiagnosticReports had, for device b:
    intelligencetasksd 11 times, AppIntentsLiveEntityService twice and
    SettingsSearchReindexService once, all the same kind of trap
    (breakpoint exception, the same exception codes in all three
    processes), and four daemons killed for not exiting in time at
    shutdown (ind, tccd, dmd, siriactionsd). None of them was an app or
    SpringBoard. A host that runs 27.0 should expect these reports and not
    treat them as its own faults until compared.

## What I did not do

- No GUI: no swipe to page 2, the Today view or the App Library (headless
  `simctl` only, as the brief required). Page 2 is from `IconState.plist`.
- The alerts were not answered, and privacy grants were not set, so each
  first screen is the one a fresh device shows.
- No disassembly, no Ghidra, no IPSW, no reference tools folder.

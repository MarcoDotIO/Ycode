# OBS-NET: what the reference simulator's guest networking depends on (2026-10-27)

Dirty-room notes, agent OBS-NET. Reference: Xcode 27.1 (27A9269), iOS 27.1
simulator runtime (24A94401), iPhone Duo device type (the only one this
runtime accepts here). Throwaway devices `ycode-test-net-1` and
`ycode-test-net-2`, both deleted at the end. No Mac setting was changed.
Test traffic: a handful of HTTPS requests to `www.example.com` and
`www.apple.com`, plus what the guest's own daemons did during boot.

Raw data, our tools and their outputs are in `research/dirty/obs-net/`
(git-ignored): `rec/netrec.c` (recorder), `probe/netprobe.m` (probe),
`boot.sh`, `probe.sh`, `matrix.sh`, `out/` (per-run logs), `host/` (the
Mac's own view for comparison), `oss/` (open-source headers used to decode
wire formats). No Apple binary was disassembled or decompiled; Ghidra and
the IPSW were not used. Level 4 was used once: a string search of the
runtime's shared cache for service names (`meta/names.txt`), to know which
names to watch.

Addresses below are replaced by documentation values (192.0.2.0/24 for the
Mac's primary network, 198.51.100.0/24 for its second network,
203.0.113.0/24 for DNS servers, `example.edu` for the search domain). The
real values are only in the raw logs.

## Method

- **Recorder** (`netrec`, ours, iOS-simulator SDK dylib, inserted with
  `DYLD_INSERT_LIBRARIES`): logs every `bootstrap_look_up{,2,3}` and
  `xpc_connection_create{,_mach_service}` (name, result, calling image),
  XPC messages on network-related connections, `mach_msg` IDs sent to
  looked-up network ports, `socket`/`connect`/`connectx`/`bind`/`sendto`
  (including the `$NOCANCEL` variants that `libsystem_dnssd` uses), the
  bytes sent and received on sockets connected to
  `/var/run/mDNSResponder`, routing-socket and kernel-control traffic,
  `necp_*` system calls, `sysctl` under `CTL_NET`, socket `ioctl`s,
  `notify_*` names, `xpc_connection_enable_sim2host_4sim`, and the
  resolver entry points (`getaddrinfo`, `DNSServiceGetAddrInfo`,
  `DNSServiceQueryRecord`, `DNSServiceCreateConnection`). It can also make
  one thing fail inside the guest process: a Mach/XPC name (look-up 1102,
  XPC to a name that does not exist), an AF_UNIX path (ECONNREFUSED), a
  socket domain (EACCES), interface `ioctl`s (ENXIO) or routing sysctls
  (ENOENT), optionally only in named processes.
- **Probe** (`netprobe`, ours, ObjC, run with `simctl spawn`): prints
  `getifaddrs`, `if_nameindex`, the routing table (`NET_RT_DUMP`), the
  guest dynamic store (all keys and values), `dns_configuration_copy`,
  `res_ninit`, `CFNetworkCopySystemProxySettings`, reachability flags, the
  first `nw_path_monitor` update, `getaddrinfo`, `res_query`,
  `dns_search`, an `nw_connection` to port 443, and an ephemeral
  `NSURLSession` fetch with transaction metrics.
- Boots: b1 (first boot, recorder in every process, everything logged),
  b2 (no recorder; probe runs p2–p4 and the denial matrix), b3 (recorder in
  every process, quiet; Safari opened on `https://www.example.com/`), b4
  (as b3, with the three `configd_sim` network services denied in the
  Safari and WebKit processes only), b5 (second device, routing and
  kernel-control traffic).
- Safari's WebKit processes are ExtensionKit extensions
  (`NetworkingExtension.appex`, `WebContentExtension.appex`,
  `GPUExtension.appex`); they do not inherit `launchctl setenv` values, so
  the recorder had to be inserted for the whole boot (`SIMCTL_CHILD_`).
  Variables passed to `simctl spawn` do not override ones set at boot.
- The Mac was heavily loaded by other agents (load average 250–980), so
  timings are not meaningful and two runs timed out in `simctl spawn`
  before the probe started; both were rerun.

## Host-side endpoints

- **The guest has no mDNSResponder.** The runtime has 329 launchd plists
  and none for mDNSResponder, networkd, symptomsd, nehelper,
  nesessionmanager or networkserviceproxy. Network-related guest jobs:
  `configd_sim` (MachServices `com.apple.SystemConfiguration.configd_sim`,
  `…DNSConfiguration_sim`, `…NetworkInformation_sim`; plug-ins
  IPMonitor, SimulatorSupport, PPPController, CaptiveNetworkSupport),
  `trustd`, `nsurlsessiond`, `apsd`, `CFNetworkAgent`.
- **`/var/run/mDNSResponder`** is the Mac's own socket (root:daemon,
  srw-rw-rw-). Guest processes reach it at that literal path: guest paths
  outside the device data directory are host paths. Every name resolution
  through `libsystem_dnssd` goes there: `getaddrinfo` (libsystem_info),
  Network.framework (URLSession, `nw_connection`, WebKit Networking,
  nsurlsessiond, trustd's OCSP fetches, apsd, Safari's Safe Browsing
  service), and libresolv's `dns_search` (AAAA through
  `DNSServiceQueryRecord`). No `DNSSD_UDS_PATH` variable is set.
- **Host Mach names**: of the names the host registers (`launchd-sim.md`
  §6.3), only `com.apple.SystemConfiguration.configd` was used for
  networking, and only by `configd_sim` (one `configopen`, then its
  session). `com.apple.SystemConfiguration.PPPController` was never looked
  up. No network XPC connection was switched to the host with
  `xpc_connection_enable_sim2host_4sim` (only `com.apple.metal.simulator`
  and `com.apple.IOSurface.Remote` were).
- **Never contacted** in two full boots and the Safari run:
  `com.apple.dnssd.service` (the dnssd XPC service), networkd,
  symptomsd, `com.apple.usymptomsd`, nesessionmanager, any NECP system
  call (`necp_open`, `necp_client_action`, `necp_session_open`,
  `necp_session_action`, `necp_match_policy`: zero calls in about 400
  processes).
- **Missing services that clients try and tolerate**: `com.apple.nehelper`
  (libsystem_networkextension asks "app-tracker-check" for a signing
  identifier; trustd, nsurlsessiond and others), `com.apple.networkserviceproxy`,
  `com.apple.commcenter.coretelephony.xpc` (34 connections at boot),
  `com.apple.commcenter.carrierspace.xpc`: each gets "Connection invalid"
  and the client continues.
- **Guest services used for networking**: `configd_sim`'s store (MIG
  `configopen` 20000 then a session; used by SystemConfiguration in
  CFNetwork, Network.framework clients, apsd, nsurlsessiond, Safari),
  `DNSConfiguration_sim` (XPC; request `{proc_name, request_op = 65537}`,
  reply `{configuration = <1876 bytes>}`; used by libsystem_configuration
  for `dns_configuration_copy`), `NetworkInformation_sim` (XPC; used by
  libsystem_configuration, MobileSafari), `com.apple.trustd` (certificate
  evaluation for every TLS connection; request keys `certificates`,
  `responses` (stapled OCSP), `policies`, `verifyDate`, `operation` 8,
  `keychainsAllowed`, `attribution`; reply keys `result`, `chain`,
  `details`, `info`), `com.apple.nsurlsessiond` (background sessions).
- **Notifications** (guest notifyd): `configd_sim` posts
  `com.apple.system.SystemConfiguration.nwi`,
  `com.apple.system.config.network_change(.nwi|.dns)`,
  `com.apple.system.config.proxy_change`,
  `com.apple.system.SystemConfiguration.dns_configuration` during its
  start. Clients register for those plus
  `com.apple.system.networkd.settings`, `com.apple.neconfigurationchanged`,
  `com.apple.system.dns(.delay|.resolver.dir)`.

## What the guest sees (Mac on Ethernet `en7` as primary, Wi-Fi `en0` second)

- **Interfaces**: `getifaddrs` returns the Mac's complete list, unchanged:
  `lo0`, `gif0`, `stf0`, `anpi0–2`, `en0–en7`, `bridge0`, `ap1`, `awdl0`,
  `llw0`, `nan0`, `utun0–8`, `vmenet0–1`, `bridge100–101`, with the Mac's
  flags (for example `en0` 0x8863 UP|BROADCAST|NOTRAILERS|RUNNING|SIMPLEX|MULTICAST,
  `utun*` 0x8051, `lo0` 0x8049), AF_LINK entries (type 6 for Ethernet-like,
  0x18 loopback, 1 for utun) and the Mac's IPv4 and IPv6 addresses and
  netmasks. `if_nameindex` gives the Mac's indices (`en7` = 10, `en0` = 15).
- **Routes**: `NET_RT_DUMP` returns the Mac's table unchanged (20 IPv4
  routes, 88 IPv6 routes, including the KAME embedded scope in link-local
  destinations). Two default routes (primary `en7` via 192.0.2.1, `en0`
  via 198.51.100.1, flags 0x41010803 with the IFSCOPE bit on the second).
- **Dynamic store** (guest `configd_sim`, 137 keys): `Plugin:InterfaceNamer`;
  `Setup:/Network/Global/IPv4` (ServiceOrder of 8 service IDs);
  `Setup:/Network/Service/<id>{,/Interface,/IPv4,/IPv6,/Proxies}`;
  `Setup:/Network/Interface/en0/AirPort`;
  `State:/Network/Global/{IPv4,DNS,Proxies}`;
  `State:/Network/Interface/<if>/{Link,LinkQuality,IPv4,IPv6,AirPort,CaptiveNetwork}`;
  `State:/Network/Service/<id>{,/IPv4,/IPv6,/DNS,/DHCP}`;
  `State:/Network/MulticastDNS`, `State:/Network/PrivateDNS`; and two
  `com.apple.sharing` keys written in the guest. The same network keys
  exist on the Mac (its store has 159 keys; the others are not network
  keys). Values: Global/IPv4 = {PrimaryInterface en7, PrimaryService <id>,
  Router 192.0.2.1}; Global/DNS = {SearchDomains [example.edu],
  ServerAddresses [3 addresses], `__CONFIGURATION_ID__` "Default: <id> 0",
  `__FLAGS__` 2, `__IF_INDEX__` 10, `__ORDER__` 0}; Global/Proxies =
  {ExceptionsList ["*.local", "169.254/16"], FTPPassive 1, `__SCOPED__`
  {en0, en7: the same two keys}}; MulticastDNS = [local,
  254.169.in-addr.arpa, 8/9/a/b.e.f.ip6.arpa]; PrivateDNS = [].
- **DNS configuration** (`dns_configuration_copy`, version 20170629): 7
  resolvers: #0 default (no domain, if_index 10 `en7`, flags 0x2, reach
  0x2, three nameservers), #1–#6 the multicast domains of
  `State:/Network/MulticastDNS` (if_index 0, flags 0x2, reach 0, order
  300000 + 200·n, timeout 5, options "mdns"); 2 scoped resolvers (`en7`
  with the three servers, `en0` with its router; flags 0x1002, reach 0x2).
  `res_ninit`: the same three servers, the search domain, options
  0x800002c1.
- **Proxies**: `CFNetworkCopySystemProxySettings` = the Global/Proxies value
  (no proxy configured on the Mac).
- **Reachability**: flags 0x2 (reachable) for a name, 0.0.0.0 and ::.
- **NWPathMonitor** (first update after 7–235 ms): status satisfied, one
  interface `en7` index 10 type wired, expensive 0, constrained 0,
  `has_ipv4` 0, `has_ipv6` 0, `has_dns` 0, no gateways. The same probe
  built for macOS and run on the Mac reports `has_ipv4` 1, `has_dns` 1,
  interfaces `en7` (wired) and `en0` (Wi-Fi) and gateway 192.0.2.1: the
  simulator's Network.framework evaluates paths without NECP and gives a
  smaller answer. `nw_connection` to port 443 reaches "ready" with the
  same path.
- **What Network.framework asks the kernel for a path**: one PF_ROUTE raw
  socket message `RTM_GET_SILENT` (type 0x11, version 5, 128 bytes,
  addrs DST|IFP, destination 0.0.0.0, empty AF_LINK IFP) answered by
  `RTM_GET` (type 4, 164 bytes, index 10, flags 0x40010843, addrs
  DST|GATEWAY|NETMASK|IFP|IFA, MTU 1500, gateway 192.0.2.1, IFP
  `en7` AF_LINK, IFA the Mac's address); the interface list
  (`NET_RT_IFLIST` sysctl, through libsystem_info); and on the chosen
  interface, on an AF_INET datagram socket, the `ioctl`s SIOCGIFMTU,
  SIOCGIFEXPENSIVE, SIOCGIFCONSTRAINED, SIOCGIFULTRACONSTRAINED,
  SIOCGIFFLAGS, SIOCGIFLINKQUALITYMETRIC, SIOCGIFFUNCTIONALTYPE,
  SIOCGIFDELEGATE. Connected TCP sockets get SIOCGCONNINFO. Other guest
  code also used SIOCGIFEFLAGS, SIOCGIFTYPE, SIOCGIFMEDIA, SIOCGIFXMEDIA,
  SIOCGIFALTMTU. Before connecting, `getaddrinfo` and Network.framework
  open the kernel control `com.apple.netsrc` (AF_SYSTEM datagram,
  SYSPROTO_CONTROL; CTLIOCGINFO gave ctl_id 7) and send one 36-byte
  version-2 request per candidate address (ifscope 0, destination
  sockaddr with port 443); each 56-byte reply gives the source address,
  RTT and connection counters, flags 0x20 (ROUTEABLE), labels and
  precedences 4/0x23, and ifindex 10.

## Denial matrix (one denial at a time, inside the probe process only)

| Denied | `getaddrinfo` | URLSession HTTPS | NWPathMonitor |
|---|---|---|---|
| nothing | ok | 200 | satisfied, en7 wired |
| `/var/run/mDNSResponder` | EAI_NONAME (8) at once | -1003 "server with the specified hostname could not be found" | satisfied |
| `…DNSConfiguration_sim` | ok | 200 | satisfied |
| `…configd_sim` (store) | ok | 200 | satisfied |
| `…NetworkInformation_sim` | ok | 200 | satisfied |
| all three `configd_sim` services | ok | 200 | satisfied |
| `com.apple.trustd` | — | -1202 (certificate invalid) | — |
| PF_ROUTE sockets | ok | -1009 "offline" | **unsatisfied** |
| AF_SYSTEM sockets (netsrc) | ok | 200 | satisfied |
| interface `ioctl`s except SIOCGIFFLAGS | ok | 200 | satisfied, type **other** |
| routing sysctls (`NET_RT_*`, so `getifaddrs`) | ok | 200 | satisfied, **no interface listed** |

`res_query` (A) sends its own UDP query (from an ephemeral bound port) to
the first nameserver of the DNS configuration; with `DNSConfiguration_sim`
denied it still worked and used the same server, so it fell back to
`/etc/resolv.conf`, which is the Mac's file. With mDNSResponder denied,
`res_query` still worked and `dns_search` (AAAA) failed (-1).

Safari (boot b3): MobileSafari opened the page; the WebKit Networking
extension resolved through mDNSResponder (connection request, then one
addrinfo request per host), connected a UDP socket to port 443 and ran
QUIC/HTTP/3 (TLS 1.3, ALPN h3, stapled OCSP and SCTs), raced a TCP
connection, asked trustd to evaluate the chain, and loaded the page. The
WebContent extension did no networking. Safari's Safe Browsing service
resolved `token.safebrowsing.apple` and connected over TCP. With the three
`configd_sim` services denied in the Safari and WebKit processes (boot b4)
the QUIC connection to the site was still set up and the page was shown
(that time from WebKit's disk cache, so the main document did not need a
fresh transfer).

## DNS wire facts (dnssd UNIX-socket protocol, open-source mDNSResponder)

- Header: 28 bytes, big-endian: version 1, datalen, ipc_flags, op, 8-byte
  client context, reg_index.
- `getaddrinfo`: `connection_request` (op 1, datalen 0), 4-byte reply 0;
  then two `query_request` (op 8, ipc_flags 0x2 = trailing TLVs) on the
  shared connection with contexts 1 and 2: body = empty control-path byte,
  flags 0x0001D000 (Timeout | SuppressUnusable | ShareConnection |
  ReturnIntermediates), interface 0, name, type A then AAAA, class IN,
  TLVs type 3 (AAAA policy, 0), 4 (failover policy, 1) and 6 (validation
  policy); each request is followed by a 1-byte `sendmsg` (the
  error-return socket passed as SCM_RIGHTS); replies are `query_reply_op`
  (68): flags, interface, error, full name, type, class, rdlength, rdata,
  TTL; then `cancel_request` (op 63) per context.
- Network.framework (URLSession, `nw_connection`, WebKit, daemons):
  `connection_request`, then one `addrinfo_request` (op 15, ipc_flags 0):
  body = empty control-path byte, flags 0xC000D000 (AllowExpiredAnswers |
  0x40000000 | SuppressUnusable | ShareConnection | ReturnIntermediates),
  interface 0, protocol 0 (both families), name; replies
  `addrinfo_reply_op` (72) with type AAAA error -65554 (NoSuchRecord,
  because the Mac has no routable IPv6 and SuppressUnusable is set) and
  one reply per A record (rdlength 4, TTL).
- No DoH/DoT: `domainResolutionProtocol` 0 (unknown) in URLSession metrics,
  `State:/Network/PrivateDNS` empty, no resolver-config TLV, no
  `com.apple.dnssd.service`.

## Other observations

- The guest's `trustd` fetches OCSP itself over the network (look-ups of
  `ocsp2.apple.com`, `ocsp.digicert.com`, TCP to ports 80 and 443) and
  asks `com.apple.mobileasset.autoasset`.
- IPv6: the Mac has only link-local and ULA (bridge) IPv6 addresses and no
  IPv6 default route, so nothing IPv6 was exercised beyond what the guest
  sees in `getifaddrs` and the route dump.
- No VPN or proxy is configured on the Mac; `utun0–8` exist (system
  tunnels) and appear in the guest unchanged.
- Network conditioning: `simctl` has no network-conditioning subcommand
  (only `status_bar` overrides for the displayed Wi-Fi/cellular state);
  the Simulator app contains no "link conditioner" string; Xcode's
  device-conditions feature (strings in DVTDeviceKit and IDEKit) is
  documented for connected devices. Because the guest uses the Mac's own
  network stack, a Mac-wide conditioner would apply to simulator traffic;
  not tested (it would change a Mac setting).
- `configd_sim` itself, at start: looks up `configd_sim` (its own store),
  then the host's `com.apple.SystemConfiguration.configd`, reads the
  interface list, posts the change notifications, and asks
  SIOCGIFDELEGATE on a utun interface.

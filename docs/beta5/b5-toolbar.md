## Requests for other workstreams

- **B5-OPENVIEWS:** a `Menu` with a primary action opens its menu when the pointer is held on it for `RunButtonMenu.holdDelay` (0.374 s), as AppKit's segment menus do; a click keeps running the primary action. Non-chosen `ViewThatFits` children still appear in the accessibility tree (with zero frames) and in `identifiedFrames`, so a driver cannot read one candidate's controls by name.
- **B5-MOTION:** take `RunButtonMenu.holdDelay` (0.374 s) into the shared timing table.
- **Shared Linux files:** `ycode-ide/WorkspaceView.swift` (B5-MOTION's) loses `CenterToolbar` and the Linux `ActivityView`, which moved to `ToolbarOverflowChrome.swift`, and `NavigatorToolbar` calls `RunStopCapsule(model:)` in place of its Run | Stop `GlassSegments`. `ShellDriver.swift`: the `YCODE_IDE_TOOLBAR5` switch name and one dispatch line.
- **Hot files:** `WorkspaceWindowController.swift` is not changed. Its `toolbarWillAddItem` still raises the fixed spaces to high (1000); `ToolbarOverflow.rank` keeps the title area and the left items above that. The New Conversation menu form it sets is replaced by `+ToolbarOverflow.swift`'s at set-up.

## Left for later (candidates)

From `window-layout.md` §2 (b5-obs 2026-11-20), not done in this branch:

- **The editor-mode group folds into one Editor Mode pop-up** (its mode's glyph with up/down chevrons) at 1350 pt (light 1325), before any text goes; Ycode moves the segmented group into "»" in one step. Needs a `ToolbarFit` step of its own on both IDEs (and the step lists in `ToolbarFit`'s tests).
- **The scheme capsule's text goes in four steps**: the scheme title truncates (1250) then goes (1225), the issue count goes (1200), the destination title truncates then goes (1175). Ycode drops both titles and the count in one step (`schemeGlyphsOnly`). Same `ToolbarFit` change.
- The exact thresholds (» at 1150 and the 25-pt steps after it) follow from the items' widths; Ycode's capsules are not all the reference's widths, so its thresholds differ by a few tens of points.
- **AppKit has one menu entry per toolbar item**: the reference's » lists Hide Navigators and Show Coding Assistant, Run › and Stop, New Conversation and Jump to Next Active Conversation, Scheme › and Destination › as separate rows. Ycode's toolbar joins each pair into one item (segmented controls, one scheme capsule), so each pair is one entry with a sub-menu (Stop inside Run ›, the destinations inside Scheme ›), and there is no Jump to Next Active Conversation row. Splitting them means separate toolbar items and new capsule measurements. Linux draws the same entries as macOS.
- The light pass's Editor Mode sub-menu lists an "Editor Only" mode; Ycode has three modes.
- Below 850 pt (live resize): Navigators and Run \| Stop leave and come back with the navigator's width (P-024, B5-MOTION); the ranks are ready for it.
- Linux: at narrow widths the navigator column clips its selector bar (P-024).
